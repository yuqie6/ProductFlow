# ProductFlow PRD

## 1. 产品定位

ProductFlow 当前实现是单商家商品视觉生产工作台。用户提供真实商品参考图和交付目标，工作流 Agent 通过对话整理商品信息、视觉体系和单图提示词，生成可编辑、可执行、可复用的图片生产工作流。

当前尚未正式商用发布，没有真实商户用户。主仓库仍处于可破坏性更新阶段，跟随研发版本可能需要重建数据库和 storage；在线运行时只维护一套 schema-v3 图、API 和执行模型。租户、计费与长期升级能力尚未实现。

用户确认的最终方向是可自托管的多商家 SaaS，项目方也部署同一产品经营自己的站点。首个正式版的隔离、体验、竞争能力与部署要求由 [产品方向与正式版路线图](ROADMAP.md) 维护，不能将当前单商家实现边界当作最终非目标。本 PRD 以下仅描述已接线能力。

## 2. 目标用户

- 需要持续生产电商商品图的独立商家。
- 需要对提示词、参考图、比例、画质和交付尺寸保留人工控制的设计者。
- 希望通过 Agent 完成需求澄清，同时保留可视化工作流编辑能力的用户。

## 3. 核心流程

### 3.1 创建商品

1. 用户进入 `/products/new`，填写商品名称。
2. 走 Agent：系统创建商品、live schema-v3 图（仅名称时为商品资料节点）、归属该商品的 AgentSession 和 AgentConversation。不创建 onboarding Task，不自动发开场 Turn。用户在对话框上传 1 至 6 张参考图，并说明图片类型；Agent 写入 intake，并用 ChangeSet 改现图。创建页上的类型和参考图可作为进入对话前的可选快捷填写。
3. 跳过 Agent：在创建页上传 1 至 6 张参考图、填写商品说明（可点「帮助生成」看图起草，规格表按返回 JSON 动态出现）和出图设定、选择图片类型，直接生成可运行画布，不创建会话。打开工作台侧栏对话时再挂画布会话。
4. Agent 检查已知信息并询问价格、风格、文字语种、文案要求、视觉体系等缺口。
5. Agent 用 apply（一条可逆）或 propose（多节点）改画布，用户在画布上确认多节点提案。
6. 关掉对话后仍可添加、连线、检查、运行、撤销和保存配方。
7. 图能跑之后，用户可在对话侧栏显式开始 Goal。Agent 请求跑图、等画布确认、再根据结果改图。一次 WorkflowGraphRun 结束不等于 Goal 完成；由用户点完成或清除。开聊不自动创建 Goal。

### 3.2 编辑和运行工作流

- 工作台可在「流程编辑」与「图片成果」间切换；无商品级显式偏好时，已有生图/证据当前图则打开默认成果，否则默认流程。用户切换后按商品记住上次主视图，清除偏好后回退条件默认。完成 ≠ 全局一律成果。成果视图覆盖全部生图节点（含未分组）与证据图，不引入第二套执行器或交付采用状态。
- 用户可新增、移动、删除和连接节点。
- 用户可用文件夹组织局部流程。
- 提示词节点维护某一种图片或某一组图片的提示词策略；种子文稿首次生成可自动采用。已有内容的补全、改写和重新生成先形成候选，由用户按业务 section 审阅。
- 视觉规范和创作要求节点使用同一候选合同。人工内容和协作内容不会被生成结果直接覆盖。
- 参考图节点一对一绑定商品图片库中的图片。
- 画面方案拥有共享文稿和文字模式；生图节点按字段保存本图差异，可恢复继承，并维护比例、分辨率、质量、参考保真度和背景。运行生图节点读取生效文稿，不重写上游已写内容。无参考边也可以跑。
- 用户可运行整张图、运行到某节点、单个节点，或对镜头/失败子集提交一次选区运行，查看运行记录，取消或重试。已有运行进行中时新请求进入排队。互不依赖的处理节点会同时调用供应商，上限为设置中的生成并发数；一张图失败不会停掉同层其他镜头。这些操作不要求打开 Agent 对话；关闭对话后与从未打开对话相同。
- 每个处理节点按输入角色分端口；缺必连输入时端口和卡片标红，该节点与该镜头的运行禁用。整图运行在仍有可入队处理节点时可用。
- 用户可把完整工作流、文件夹或多选节点保存为自己的配方。
- 创建页「从配方创建」可选择已保存的完整配方，填写新商品名称并上传 1 至 6 张参考图；预览取消不创建商品，确认把商品与第一张图一起保存，不创建 Agent 会话。同一次确认重试返回同一商品。新图采用目标商品资料，素材占位需重新选图，不继承来源绑定或生成结果。实现与回归：`go/internal/product/recipe_create.go`、`recipe_create_test.go`、`web/e2e/canvas-asset-recipe.spec.ts`。
- 画布文件夹只提供一层视觉组织，不支持嵌套、独立运行、取消或重试。

### 3.3 管理图片

- 商品图片库保存上传图、工作流生成图、连续生图转入图和局部编辑结果。
- 目录树提供系统分类、图片类型、来源和用户文件夹。
- 用户可搜索、排序、预览、重命名、移动、批量选择、下载和生成交付图。
- 用户可对已有商品图做消除、换字或局部重绘。新图保留来源；失败不替换节点当前结果。检查器打开时可把结果采用为该生图节点的当前图，或只留在图库。
- 用户文件夹只支持一层；删除文件夹只解除组织关系，不删除图片或破坏节点、封面和 lineage 引用。
- 节点绑定图与图库资产共享同一个 ProductImageAsset 身份。
- 商品封面自动选择；封面只承担列表展示。

### 3.4 连续生图

- 用户建立图片会话，选择基图和至多 6 张上下文参考图。
- 每轮可以设置候选数量、尺寸和高级图片参数。
- 任务支持排队、运行进度、取消、失败重试和候选分支。
- 满意结果可下载、保存到全局素材库，或保存到某个商品的图片库。

### 3.5 全局素材库

- `/media-library` 提供跨商品长期保存的全局素材入口，支持搜索、文件夹、标签、归档/恢复、上传和批量组织。
- 连续生图候选可以保存到全局素材库。
- 工作流子图库只保存全局素材的使用关联，同一媒体可以被多个工作流使用，不复制媒体字节。
- Agent 只能发布可确认的素材整理 Draft；用户确认后才应用重命名、移动、标签和归档。

### 3.6 全局 Agent Dock

- 登录后的应用壳层提供 Global Agent Dock，用于 Session/Task 列表、搜索、新建、归档、打开工作区、取消任务和确认全局素材整理 Draft。
- 商品工作流的编辑、运行、取消和重试继续由商品工作台负责；Dock 不取代画布或 WorkflowRun。

## 4. 核心对象

- `Product`：商品身份和基础信息。
- `MediaObject`：媒体字节、类型、尺寸、校验状态和 storage 路径。
- `ProductImageAsset`：商品命名空间中的图片身份、来源、目录和派生关系。
- `MediaLibraryAsset`：全局素材库中的逻辑图片身份、来源快照、组织和归档状态。
- `WorkflowMediaLibraryAsset`：全局素材到某个工作流子图库的使用关联。
- Product intake：图种、数量和参考图 ID，存在 Product 上。商品路径不再新建 `WorkflowDraft`。
- `WorkflowGraph`：当前 schema-v3 DAG。
- `WorkflowGraphNode` / `WorkflowGraphEdge` / `WorkflowGraphGroup`：画布结构。
- `WorkflowGraphRun` / `WorkflowGraphNodeRun` / `WorkflowGraphArtifact`：运行状态和产物。
- `WorkflowRecipe` / `WorkflowRecipeVersion`：用户主动保存的完整配方或局部片段。
- `AgentSession`：长期交流容器、标题、摘要和任务索引。
- `AgentTask`：一个业务目标和一次任务专属 run。商品路径上用作显式 Goal：跑图结束不等于完成。
- `AgentConversation` / `AgentTurnProjection`：ProductFlow 侧的 Agent 会话和 Turn 投影。
- `ImageSession`：独立连续生图会话。
- `DeliveryRenditionJob`：按交付规格导出图片的异步任务。
- `ProviderProfile` / `ProviderBinding`：供应商档案与用途绑定。

## 5. 当前页面

- `/home`：登录后的功能导航与真实商品素材展示。
- `/products`：商品列表和自动封面。
- `/products/new`：全屏 Agent 创建流程。
- `/products/:productId`：Agent、工作流画布、节点详情、运行记录、配方和图片库。
- `/image-chat`：连续文/图生图。
- `/media-library`：全局素材库。
- `/settings`：供应商和运行时设置。
- `/help`：产品内帮助，投影 `USER_GUIDE.md` 的当前页面操作。

## 6. 产品合同

- 走 Agent 时，商品名称即可进入工作台；出生即 live 图。1 至 6 张通过媒体校验的参考图和图片类型在对话中提交（创建页也可作为可选快捷填写）。直接创建仍须在表单上提交参考图和图片类型，且不创建会话。商品识别信息是否充分由 Agent 和用户审阅，后端不声称能自动证明图片真实性。
- 图片类型初始不选中；每个选中类型的数量为 1 至 6、默认值为 2，总计划最多 30 张。
- 用户确认的结构化事实高于未确认输入，未确认输入高于 Agent 图片观察；冲突事实不能通过最终 Draft 确认。
- Agent 可以整理、重命名和移动商品图片库资产，并按需读取单张图片内容；不会把整个图库一次性放入模型上下文。
- 每个参考图节点绑定一个明确的 ProductImageAsset。
- 视觉体系是工作流级共享约束；单图提示词可以记录明确例外。
- GenerationSpec、provider 实际执行参数和实测输出分别记录；DeliverySpec 只产生确定性交付图，不重新生图或覆盖原图。
- 所有生成结果进入商品图片库，不定义废稿或交付清单状态。
- Agent 对话可随时关闭。关闭或从未打开时，画布的添加、连线、检查器、运行、撤销和配方保持可用；Turn 失败或状态不明不得锁画布。
- 工作流复用只来自用户主动保存的配方。
- Provider purpose 固定为 `prompt`、`agent` 和 `image`。

## 7. 非目标

- 多租户、团队角色、计费和用量结算。
- 自动发布到电商平台或广告平台。
- 自动判定并删除用户不满意的生成图。
- 在 Agent 上下文中一次加载整个商品图库。
- 长期保留旧运行时模型的兼容读取器、双序列化、409 兼容桩，或为已部署数据写回填/冻结/归档闸门。

## 8. 成功标准

- 用户可以在 Agent 对话中提交参考图和图片需求，确认草案后写入工作流图；也可以在创建页直接生成画布。推荐套图覆盖封面主图、一页一钩的卖点序列、规格、选款、场景和细节。
- 封面是商品主图摄影，不是购物 App 货架截图；详情卖点图与封面分工，多张时钩子不重复。
- 用户可以继续手工编辑节点、连线、文件夹、提示词、参考绑定和生成规格。
- 工作流生成图、连续生图转入图和上传图在同一商品图片库中可管理；跨商品长期素材进入 `/media-library`。
- Provider 配置、Agent Turn、工作流运行和图片任务在失败或重启后有明确状态。
- 当前代码和文档只描述一套在线工作流合同。
- 主仓库不承诺已部署实例的无损升级；需要稳定快照的部署自行 fork。
