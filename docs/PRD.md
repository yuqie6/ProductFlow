# ProductFlow PRD

## 1. 产品定位

ProductFlow 是单商家商品视觉生产工作台。用户提供真实商品参考图和交付目标，工作流 Agent 通过对话整理商品信息、视觉体系和单图提示词，生成可编辑、可执行、可复用的图片生产工作流。

当前版本服务个人项目和 live demo，但已部署实例的数据升级不能依赖重置。迁移窗口需要保留最小不可变历史快照、canonical 资产映射和 Agent 重建入口；在线运行时仍只维护一套 V2 schema、API 和执行模型。SaaS 的租户、计费与长期兼容策略不属于当前版本。

## 2. 目标用户

- 需要持续生产电商商品图的独立商家。
- 需要对提示词、参考图、比例、画质和交付尺寸保留人工控制的设计者。
- 希望通过 Agent 完成需求澄清，同时保留可视化工作流编辑能力的用户。

## 3. 核心流程

### 3.1 创建商品

1. 用户进入 `/products/new`，填写商品名称。
2. 图片类型初始均不选中；用户选择需要的类型后，该类型数量初始化为 2，可在 1 至 6 之间独立调整，全部类型总数最多为 30。
3. 用户上传 1 至 6 张参考图，并应包含至少一张能识别真实商品或权威商品渲染的图片。后端确定性校验数量、归属、字节和媒体格式；参考内容是否充分由 Agent 和用户审阅确认。
4. 系统创建商品、WorkflowDraft 和 AgentConversation。
5. Agent 检查已知信息并询问价格、风格、文字语种、文案要求、视觉体系等缺口。
6. Agent 输出商品事实、视觉体系、图片计划、每张图的提示词、参考绑定和生成规格。
7. 用户检查并确认草案。
8. 系统物化 schema-v2 工作流，通过流式事件逐步显示文件夹、节点和连线。
9. 创建页平滑进入商品工作台，右侧继续原 Agent 对话。

### 3.2 编辑和运行工作流

- 用户可新增、移动、删除和连接节点。
- 用户可用文件夹组织局部流程。
- 提示词节点维护某一种图片或某一组图片的提示词策略。
- 参考图节点一对一绑定商品图片库中的图片。
- 生图节点维护比例、分辨率、质量、参考保真度、背景和文字策略。
- 用户可运行整个 DAG 或单个节点，查看运行记录，取消或重试。
- 用户可把完整工作流、文件夹或多选节点保存为自己的配方。
- 画布文件夹只提供一层视觉组织，不支持嵌套、独立运行、取消或重试。

### 3.3 管理图片

- 商品图片库保存上传图、工作流生成图和连续生图转入图。
- 目录树提供系统分类、图片类型、来源和用户文件夹。
- 用户可搜索、排序、预览、重命名、移动、批量选择、下载和生成交付图。
- 用户文件夹只支持一层；删除文件夹只解除组织关系，不删除图片或破坏节点、封面和 lineage 引用。
- 节点绑定图与图库资产共享同一个 ProductImageAsset 身份。
- 商品封面自动选择；封面只承担列表展示。

### 3.4 连续生图

- 用户建立图片会话，选择基图和至多 6 张上下文参考图。
- 每轮可以设置候选数量、尺寸和高级图片参数。
- 任务支持排队、运行进度、取消、失败重试和候选分支。
- 满意结果可下载、收藏到画廊或保存到某个商品的图片库。

## 4. 核心对象

- `Product`：商品身份和基础信息。
- `MediaObject`：媒体字节、类型、尺寸、校验状态和 storage 路径。
- `ProductImageAsset`：商品命名空间中的图片身份、来源、目录和派生关系。
- `WorkflowDraft` / `WorkflowDraftRevision`：Agent 产出的可确认工作流草案。
- `ProductWorkflow`：当前 schema-v2 DAG。
- `WorkflowNode` / `WorkflowEdge` / `WorkflowFolder`：画布结构。
- `WorkflowRun` / `WorkflowNodeRun`：运行状态和结果。
- `WorkflowRecipe` / `WorkflowRecipeVersion`：用户主动保存的完整配方或局部片段。
- `AgentConversation` / `AgentTurnProjection`：ProductFlow 侧的 Agent 会话和 Turn 投影。
- `ImageSession`：独立连续生图会话。
- `DeliveryRenditionJob`：按交付规格导出图片的异步任务。
- `ProviderProfile` / `ProviderBinding`：供应商档案与用途绑定。

## 5. 当前页面

- `/products`：商品列表和自动封面。
- `/products/new`：全屏 Agent 创建流程。
- `/products/:productId`：Agent、V2 画布、节点详情、运行记录、配方和图片库。
- `/image-chat`：连续文/图生图。
- `/gallery`：收藏画廊。
- `/history`：V1 workflow、用户模板和 Canvas Agent 的只读归档、导出与 Agent 重建入口。
- `/settings`：供应商和运行时设置。
- `/help`：当前产品帮助。

## 6. 产品合同

- 用户必须提供 1 至 6 张通过媒体校验的参考图后才能进入 Agent 创建流程；商品识别信息是否充分由 Agent 和用户审阅，后端不声称能自动证明图片真实性。
- 图片类型初始不选中；每个选中类型的数量为 1 至 6、默认值为 2，总计划最多 30 张。
- 用户确认的结构化事实高于未确认输入，未确认输入高于 Agent 图片观察；冲突事实不能通过最终 Draft 确认。
- Agent 可以整理、重命名和移动商品图片库资产，并按需读取单张图片内容；不会把整个图库一次性放入模型上下文。
- 每个参考图节点绑定一个明确的 ProductImageAsset。
- 视觉体系是工作流级共享约束；单图提示词可以记录明确例外。
- GenerationSpec、provider 实际执行参数和实测输出分别记录；DeliverySpec 只产生确定性交付图，不重新生图或覆盖原图。
- 所有生成结果进入商品图片库，不定义废稿或交付清单状态。
- 工作流复用只来自用户主动保存的配方。
- Provider purpose 固定为 `prompt`、`agent` 和 `image`。
- V1 历史只读查看、下载、导出和 Agent 重建；重建只生成待确认的 V2 Draft，不恢复 V1 编辑器或执行器。

## 7. 非目标

- 多租户、团队角色、计费和用量结算。
- 自动发布到电商平台或广告平台。
- 自动判定并删除用户不满意的生成图。
- 在 Agent 上下文中一次加载整个商品图库。
- 长期保留旧运行时模型的兼容读取器；迁移窗口的不可变历史快照读取属于有边界的升级能力。

## 8. 成功标准

- 用户可以从参考图和图片类型选择完成 Agent 澄清、确认和工作流物化。
- 用户可以继续手工编辑节点、连线、文件夹、提示词、参考绑定和生成规格。
- 工作流生成图、连续生图转入图和上传图在同一商品图片库中可管理。
- Provider 配置、Agent Turn、工作流运行和图片任务在失败或重启后有明确状态。
- 当前代码和文档只描述一套在线工作流合同。
- 已部署实例的 V1 切换必须完成 source/archive/canonical 对账和备份恢复证据，不能以重置数据代替迁移。
