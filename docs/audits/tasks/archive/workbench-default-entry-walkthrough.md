### 摩擦点

1. **默认流程编辑 + 密图**：复访已出图商品时，首屏是节点/边噪音；要看齐套结果需再点「图片成果」或依赖底部胶片条摘要。
2. **成果与交付规格分离**：采用前须在检查器设交付规格；成果卡可点采用，但规格不在成果面内联引导（文案合同是「请先在检查器设置」）。
3. **采用/视觉依赖新 API**：共享旧 API 下点击采用或加载视觉方案只得英文「Not Found」，用户无法区分「未设规格」与「后端未就绪」。
4. **导出入口条件隐藏**：无 current adoption 时不渲染导出控件，失败后也无导出位。
5. **配方复用冷启动**：创建页配方 Tab 与工作台预设入口齐全，但空库时只能看到空态；片段「存为配方」在流程节点工具条，成果视图无对等入口。
6. **首次制作仍需流程**：USER_GUIDE 要求进台后先跑视觉/创作/提示词再出图；空成果态不能替代构图与运行范围控制。

### 建议（可复核）

**结论：现在不要做「全局默认一律切到图片成果」。**

依据：

- 实现事实：默认硬编码 `flow`（Surface + CanvasPanel）；切换器一键可达成果；定位可回到流程。
- 复访已出图场景：成果视图明显降低「找齐产出」成本（本样本 10 项分区 vs 密画布+胶片条）。
- 首次创建/改结构/改文稿/控运行范围：仍以流程为主路径；空图时成果页几乎无内容。
- 采用→导出与视觉选定在共享栈上未跑通；切换默认不能修复该缺口，也不应在缺口下宣称交付链体验达标。

**若后续做默认入口实现单，建议合同（非本任务实施）：**

1. 保留流程为「无可用图像产出」或「用户上次选流程」时的默认；或
2. 当图上已有生图/证据项且至少一枚有当前图时，进入工作台默认 `results`，并保留显式切回流程；
3. 不要无条件全局 `results`。
