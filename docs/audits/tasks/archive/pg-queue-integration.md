### 共享切换预检（2026-09-09）

主代理刷新进程发现共享 API/worker/dispatcher/Pi/Web 已在运行，旧 WSL 停机快照不再有效。仅只读查询：旧信封 pending/sent=0，consumed=357，Agent sync dead=5；Graph 无运行中，图片会话 unknown=1；Agent projection queued=1、cancel_requested=1、unknown=19，另有待确认/待输入。不能因为信封已空就判断全部业务已排空，尤其不能自动复活五条 dead 同步或重放 unknown。候选不碰共享服务；集成切换须复查这些未收敛记录的实际业务状态和运行资源归属。

### 主代理候选初审与固定边界

候选早期草稿的 `MaxAttempts=1`、将所有错误取消、从最新 River 行推算业务执行轮均未获准集成。修正合同：基础设施错误由 River 有限重试；已持久化业务终态结束任务；Busy/Later 使用 snooze。执行身份持久化于业务受理/显式重试，自动恢复和候选续跑不换身份，在现有领取行锁内比较身份与商家。不可只携带未验证的 fence 参数，也不能依赖会被清理的队列历史维持身份。

River 原生 `DiscardedJobRetentionPeriod=-1` 和 `CancelledJobRetentionPeriod=-1` 可保留停止记录；业务恢复排除同一执行身份的停止任务。公平判断仍持有现有 generation admission lock，依据实际生成槽占用和就绪商家；单 Worker 并发设置不等于跨 Worker 的全局容量。

### 当前候选与迁移事实

root 独占所有生产、schema、依赖和活文档。pg_queue 仅 Delivery/LocalEdit 测试；capacity_baseline 仅 ImageSession 测试，当前补真实 SIGKILL 文件；river_tools 已交付容量工具，主代理待固定版本实测。各自任务保留审核与提交证据。

River 全历史迁移不能放进同一个 SQL 事务：实际 PostgreSQL 在版本 006 报 `unsafe use of new value "pending" of enum river_job_state`（55P04）。最终实现使用 River 原生逐版本事务，在既有迁移 advisory lock 下串行；后续业务 schema 仍单事务回滚。失败后重跑从已提交 River 版本继续。此前草稿“River 同事务迁移”不再有效；业务受理与 River InsertTx 的共同事务仍有实际回滚证据。

已通过 queue 的实际 PG 事务/嵌套回滚、停止记录不复活、旧执行身份拒绝、基础设施重试不重复效果、停机取消后 checkpoint 和双客户端无通知轮询；schema 全包通过。Graph 小规模真实 River Worker 公平回归通过。主代理修正了商品媒体补偿包装无法被 InsertTx 识别的问题，并验证自动 Delivery 入队及外层/嵌套回滚。Agent SubmitTurn 改为预留 projection 与 job 同事务，Gateway 在提交后绑定；全 Agent 通过 146.187s。CGO/WebP 四运行命令 Docker 构建通过早期候选，最终候选仍需固定后构建与公平门。
