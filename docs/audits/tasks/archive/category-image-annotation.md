## 实施合同与排他范围（主代理冻结）

- quota_policy 排他实施 go/internal/imageeval/annotation*.go 及必要的现有传输基础复用、go/cmd/productflow-image-evals/ 的 annotate / prepare-annotations 命令与测试。原 Judge / GateSlot / RunReport 和历史证据含义保持；不改生成链。主代理持有 justfile、活文档和真实运行验收；其他代理不得写此范围。
- 独立 image-annotation.v1：复用四维 Scores，新增有资产依据的优缺点、严重程度、观察/推测区分、不确定项与需验证建议。模型按类别与图种提出展示重点，报告保留这些标准及依据；不把启发式 gold 当独立确认的事实真值。
- 输入为显式 selection，所有目标、身份参考、质量对照记录路径/角色/SHA；既支持原始真实图的 reference 标注，也支持显式候选与真实图 comparison。缺少候选不得自动变为 reference 模式，缺少对照不得宣称不弱于真实图。prepare-annotations 从现有池输出 reference 标注选择，候选比较需显式绑定，不按数组顺序猜测。
- 状态与聚合区分模型失败/未知、材料不充分与有效评分；类别×图种×variant 显示分母和覆盖率，关键事实/身份错误单列且阻止不弱于对照的结论。四维对照差异可见，不能只剩总均分。
- 报告独立输出 JSON 与可读报告（复用可用报告工具，至少 Markdown），记录 selection/schema/prompt/模型/代码版本/图片 SHA 与时间。不建立新的 latest 指针；禁止覆盖旧输出目录，原池和历史 runs 只读。模型输出严格校验与依据引用有效性；报告不存凭据或未经处理的供应商错误内容。
- 验证顺序：执行者完成包测试和命令测试后一次交付；主代理审核并使用归一化 8-case 诊断池及明确绑定的已有候选做独立真实多模态验证。仅调用评委，不创建商品/工作流或调用生图模型；8-case 证据不代表完整 195-case 数据集已标注。
