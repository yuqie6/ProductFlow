## 问题来源

现有语言/主题是浏览器偏好，商家名称与站点 provider 配置属于不同所有者。一个账号自有一个商家，设置界面应直接表达本人和站点权限，不建设团队设置体系。

## 做成什么样

本人可在账户页面保存个人语言/主题与商家名称。站点 `/settings` 只给管理员；界面语言不改变商品输出语种。沿已有组件和字段实现，不新增无业务读者的设置。

## 前置与并行

[设计校准](archive/saas-design-alignment.md) 已完成；[账户任务](saas-account-team.md) 提供本人页面时复用，若一起交付则由同一主代理整合，不以团队能力为前置。隔离 PG/browser，无需真实 provider。

## 修改范围与所有权

认领后按字段实际读写者冻结 auth、preferences、Account、API/types/i18n 和必要 schema/tests；共享文件单写者。

## 合同

- 只写本人偏好和自有商家资料。locale/theme 沿现有枚举，不新增生产参数或商家自带 provider 密钥。
- 本人设置跨会话可恢复，不将共享浏览器旧值静默上传给新账号；退出后清账号缓存。
- 使用已有模型；并发语义按字段风险明确，语言/主题不强制新增独立 revision/409 协作协议。
- 如增加时区，它只影响显示/筛选，UTC 持久事实与已受理任务不变；没有日期业务读者时不提前引入。
- 站点凭据、模型和运行配置仍属管理员；不恢复旧二次解锁机制。

## 怎么验收

本人/他人读写隔离、刷新与换账号、无效枚举、保存失败恢复；现有四语明暗与桌面/手机可操作。相关 PG/Go 与 Web 回归、静态检查及 docs-check，不跑无关图片实验。
