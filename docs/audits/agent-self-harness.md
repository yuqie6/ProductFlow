# Agent 自进化组

本组交付一个在既定目标、权限、数据和预算内自动发现失败、定位根因、产生修改、验证和迭代的系统。正常路径只在最终进化版本提交给用户时审批一次。改进对象覆盖影响 Agent 任务成效的指令、工具、Node 适配和必要 Go / Web 实现；模型权重训练不在当前合同。

2026-09-05 用户确认按完整结果重划业务组。本文件替换旧 Self-Harness P3–P7 与后加 S0–S6 的未来路线；P1/P2/P2b 的实现和历史归档保留。旧的 Prompt-only、每簇人工抽读、逐阶段人工交接、Steer/记忆作为发布前置均不再适用。当前没有自动进化控制器，以下目标不得写成已实现。

## 交付范围

- 本组拥有自动改进流程的端到端交付：固定输入、隔离实验、失败挖掘、候选生成、可信验证、迭代记录、停止与最终审批交付。必要的测试适配纳入本组任务序列，复用公共实现，不等待其它组逐轮接单。
- 普通人工工程修复由 [Agent 质量组](agent-eval-system.md) 承接。[eval-skills](tasks/eval-skills.md) 的人工候选与结果不算本系统的自动收益。
- 每轮使用已发布的固定评测与业务合同。评测器在候选之外运行，候选不能修改其规则、隐藏材料或成绩；独立验证不要求另一个工作组人工运行。
- 已知普通生产故障继续正常修复，不为保存实验基线留在线上；自动进化在固定隔离版本中进行。共享代码变更仍由协调者预约排他范围，组不永久占有模块。
- 现有 [eval-development-baseline](tasks/eval-development-baseline.md) 是一次性启动输入任务，仍有真实前置阻塞。任务状态和已认领者保持原合同；它不定义未来每轮的人工流程。

## 正常运行合同

```text
已配置的目标 / 权限 / 预算 / 数据与评测版本
  → 自动执行任务并发现失败
  → 自动归因和选择有证据的问题
  → 隔离生成指令或代码候选
  → 自动回归、比较、拒绝或迭代
  → 冻结最终候选并独立验收
  → 用户一次最终审批
  → 按批准版本发布并记录结果
```

1. 自动选题须区分事实与假设。缺少必要用户目标或工具结果时记录证据不足；不能把所有失败归因到 Skill。初版直接分析有界开发轨迹即可，封闭分类词表、聚类平台和单独 Miner 服务不作为前置。
2. 同一轮内部接受的候选只更新隔离实验父版本，不修改生产。保留失败尝试、修订和成本；预算内可以继续尝试，达到停止条件输出完整结果。
3. 最终审批前自动完成版本冻结、独立验证和报告。用户看到改了什么、为什么、比较结果、回归/副作用风险、总成本与恢复方式；批准绑定精确工件，不是允许下一轮任意改动。
4. 没有合格候选、预算耗尽、输入不可信或越出授权范围时自动停止，不把人工选题、诊断、逐候选审批或手修补丁当正常兜底。系统报告阻塞或无改善，不能伪造成功。
5. 已设定的权限、费用限额和有效数据是运行配置。未配置则不可启动；运行中不能提高自己的权限或预算。人工标签校准等基础材料建设单独记录，不伪称每轮不需要人就等于不需要任何可信输入。
6. 批准后由已有构建/发布方式应用该精确版本，无第二次例行人工发布确认；内容、依赖或有效配置变化即不再沿用原批准。审批与发布接口尚未实现，不能将此条理解为当前自动部署授权。

## 一条组内交付序列

以下三项是发布任务的结果边界，尚未同时发布为 issue。先完成前项的可执行交付，再发布下一项，不设并行的第二套阶段表。

| 顺序 | 可独立验收的结果 | 必要证据 |
|---|---|---|
| 固定实验与自动验证 | 同一固定业务版本可以在隔离环境重放有效问题、构建候选并调用固定验证；系统拒绝篡改评分和凭据访问 | 固定代码/数据/评测身份、父版本真实失败、环境重建与隔离测试；必要适配在本组建设 |
| 自动发现到改进 | 从获准执行记录自动选题、诊断、产生修改并完成候选验证；包含一条真实代码级问题，不能全部只改 Prompt | 记录中无人挑题、手写诊断或补丁；自动候选修复父版本失败，相关合同与安全回归通过；明确一次案例不能证明普遍收益 |
| 多轮与最终审批 | 有界多轮运行，失败不丢弃，正常路径只在最终版本审批一次；批准、拒绝、取消、无改善、超预算和版本漂移均可验收 | 多个问题上的成本与效果、独立验收、完整谱系、一次批准应用精确版本及恢复演练 |

初始开发输入依赖当前考题校正的固定交付，这是本次重组无法凭文档消除的启动阻塞。取得可用输入后本组自行编排，不等待 Agent 质量组全部 L0–L6、nightly 或日常候选完成。若特定实验缺乏真实隐藏材料或语义裁判校准，就限制其结论，不声称生产质量提高。

组内后续可建设当前缺失的验证入口与受限部署，调用已有公共评测实现。涉及被测行为与评测合同的工作分成先后任务，分别审核并冻结；修改候选时正式评分不变。

## 修改权限与最小实现

一个候选验证一个因果假设，必要时跨层。工具参数/结果、Graph 业务实现、事务、状态查询与必要前端投影均可在事前批准范围内提出代码补丁。权限/确认语义、评分权威、生产迁移、凭据和发布授权不由候选修改；新工具或合同变更超出当前范围时自动拒绝该提案，不临时向用户追加审批步骤。

首期用一个离线编排入口复用编码执行器、Git 补丁和现有评测产物。职责分写权不等于四个常驻服务，不另建任务板、通用版本中心或生产 shell 工具。具体执行器接入以固定版本的最小实验裁定；不同时安装多个搜索框架。

- 编码和构建环境不持生产 DB/storage、共享 .env、SSH/Git 凭据或宿主 Docker socket。安装脚本与测试同样是不可信执行；模型调用和资源受外部预算控制。
- verifier 与隐藏材料独立于候选执行环境；独立读取业务后置条件和外部调用记录，不能只信候选自报成功。后端问题使用真实隔离 PG 及相关故障测试，替身结果不代替真实 provider 结论。
- 问题包保留必要事实与引用关系，缺失明确标记。每次实验关联代码/构建/依赖、harness/Skill、模型请求选项、任务/数据、verifier、控制器和环境版本。复用已有记录，不新增多个身份注册表。
- 成本记录全部模型与评测尝试、人工审查时间和无法取得的 usage；上限从可信配置读取，不由候选提高。不为跑到成功增加次数或丢掉失败项。
- 代码发布走正常构建部署，不通过 harness_hash 热替换 Node/Go。代码恢复与已发生数据/付费副作用分别处理；首期生产迁移不自动执行。
- 线上既有 Turn 和 WorkflowRun 的在途行为按相关合同验证；确实需要时采用维护/排空窗口，不引入仓库已禁止的双运行时或旧数据迁移路径。

## 验证与出口

当前 G1 = 完整自动进化后一次最终人工审批；状态为缺失。原 G2 的无人工晋升不在本期交付目标，不作为“自进化完成”的必要条件。

[Agent 质量测量合同](agent-eval-system.md#self-harness-评测用途)定义集合和评分语义，控制器自动执行固定版本。开发反馈与用于筛选的隐藏回归均不等于最终独立验收；暴露后的材料不能继续当作未见数据。合并或更新父版本形成新候选并重验。

既有纯指令实验的初筛门槛保留：双方 k=3；开发/隐藏回归均不降且至少一项提高，净增至少两个任务·试验；中位 tokens 增幅不超过 15%；指令总量不超过 16 KiB、overlay 不超过 10 KiB；负例不劣化且任何越权/未确认副作用直接拒绝。这些是筛选条件，不证明统计显著性，不将文本字节限制套到 Go 补丁。

代码级实验在开始前固定主要业务指标、成本限额、回归边界、样本量与停止规则，外部 verifier 按该规则运行。父版本失败、候选通过的确定性回归证明修复；在未见场景上的配对运行证明效果范围。保留不确定区间与无改善结论。未校准材料只能用于诊断，不能用最终人工批准豁免缺失的安全或有效性证据。

最终生产批准还须具备该修改面相关的执行可靠性和安全证据。涉及模型行为时引用有效的 D-08 与 L5 证据，不能拿历史版本 run_id 放行新版本；现有产品通过率门槛不因改组降低。G1 完成记录同时包含自动化程度、效果、成本和一次审批证据，不能只填“测试通过”。

## 收益归因与暂停条件

人工工程 A→B 与自动改进 A→C 分别报告；从更新后的 B 启动要明确新起点。无需等人工 B 完成才能建设控制器，也不刻意保留生产 Bug。系统级与 Prompt-only 对照固定共同父版本、生产/提案模型、评测规则和总预算；使用更强外部编码模型单列，不冒充同模型 Self-Harness 效果。

同模型自动挖掘、提案与验证循环是首期研究基线。问题输入来自系统自动选择的开发证据；当前外部编码助手搭建控制器属于工程建设，不计作该系统自动进化。

没有稳定收益时停止扩大投入，检查数据、搜索或修改面的真实瓶颈。Steer、长期记忆、复杂种群、自动合并策略、无人工发布与元进化均按具体证据另行立项，不挂成当前完成条件。自动挖掘、提案、验证与停止保留为核心要求。
