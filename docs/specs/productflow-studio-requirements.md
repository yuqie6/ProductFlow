第一版只追一个结果：商家能把一件真实商品稳定地做成一套可修改、可复用、可交付的商品图。

## 1. 要补的能力

工作台主区提供两种视图，读写同一张 live graph。切换视图不保存第二份图，不改变执行语义。

| 能力 | 用户看见 | 实现边界 |
|---|---|---|
| 镜头列表 | 默认主区。每个会生图的分组一行：图种、张数、状态、最新缩略图、运行此镜头 | 投影现有 group + image_generation 节点 |
| 画布 | 要改结构时切换。六类节点、连线、一层分组 | 现有 schema-v3 画布 |
| 生成套图 | 商家文案。按镜头展示进度 | 语义仍是现有整图 DAG：先内容节点，后各镜头生图 |
| 创建页推荐套图 | 快捷勾选常用图种 | 不另建计划对象；仍受 1–6 / 总量 30 约束 |
| 官方场景配方 | 配方库「官方」分区四个片段 | 与用户配方同一套 preview/apply |
| 出图后局部修 | 对已有结果消除、换字、局部重绘、裁切 | 不是第七类节点；写回同一 `ProductImageAsset` 谱系 |
| 平台交付预设 | 淘宝/京东/Amazon 等 DeliverySpec 模板 | 不重新生图；不是发布到店铺 |
| 保真核对清单 | 外形、颜色/材质、logo/文字、文字策略 | 人工结论；不用自动分数替代 |

「添加场景」在镜头和画布都能用，一次落下分组 + 提示词 + 一张生图。

## 2. 明确不做

- 女装平铺一键上身、虚拟模特库、姿势裂变。
- 粘竞品详情链接做整页复刻。
- 一次批处理整个店铺几百 SKU。
- 图生视频、视频翻译、直播切片。
- 多人同时改同一张图。
- 新开 `/tools` 技能首页或 18 个互不相通的技能页。
- 社区配方市场。
- 去水印独立产品、批量 200 张超清货架。
- 自动发布到店铺、按平台审核规则拒图、图片内文案翻译工具。
- 商品删除/归档作为本增量的附带范围。
- 把镜头列表做成第二份图权威。

## 3. 官方场景配方

第一版只预置四个片段配方，全部落在现有六类节点上：

| 官方配方 | 作用 | 默认倾向 |
|---|---|---|
| 白底主图 | 补或更新 `hero` 镜头 | 浅底、商品居中、无文案、参考保真高 |
| 使用场景 | 补或更新 `scene` 镜头 | 使用环境、商品是主角、无文案 |
| 细节特写 | 补或更新 `detail` 镜头 | 1:1、材质工艺、无文案 |
| 卖点信息图 | 补或更新 `selling_point` 镜头 | 文案必须、语种沿用商品设定 |

- 镜头已存在则预览为配置合并；不存在则添加场景组。
- 官方配方是版本化种子，不在前端写死节点数组。
- 更新不得静默改用户已经应用的 graph。
- 下线只阻止新应用。
- 每个官方配方要有缩略图、适用图种、所需输入和真实 provider 样本。

## 4. 局部修

商家循环是改那 20%。局部修是对已有 `ProductImageAsset` 的操作。

入口：镜头缩略图、生图节点结果、商品图片库预览。

| 操作 | 说明 |
|---|---|
| 消除 | 去掉指定元素 |
| 换字 | 替换画面中的指定文字 |
| 局部重绘 | 圈定区域按文字说明重绘 |
| 裁切 | 默认定性裁切，可只走 DeliverySpec；用户明确要重绘构图时才烧模型 |

结果：

1. 生成新的 `ProductImageAsset`，谱系指向来源。来源保留。
2. 用户可「用作该生图节点的当前结果」，或只存进图库。
3. 失败时节点当前结果不变。
4. 没有 edit 能力的 provider 必须可见失败，不得假装已改。

请求至少包含：`source_asset_id`、`operation`、`instruction`、需要时的 mask、`expected_source_revision`、`idempotency_key`。浏览器缩放后的笔刷坐标必须反算到源图像素，不发送 viewport 坐标。

完成后三个动作：「仅存图库」「采用为当前结果」「继续编辑」。采用 current 可撤销为上一资产引用，但不删除资产。

## 5. 平台交付预设

DeliverySpec 模板，不是新节点，不烧模型。

| 预设 | 画幅 |
|---|---|
| 淘宝/天猫首屏 | 3:4 |
| 京东主图 | 1:1 |
| Amazon 主图 | 1:1 |
| 详情竖图 | 3:4 |
| 场景横图 | 4:3 |
| 自定义 | 用户宽高 |

应用预设只改选中生图节点或导出任务的 DeliverySpec。已有生成源图时导出走 rendition job。平台名称只是内置模板，不构成合规保证。

套图导出：安全化文件名、manifest、缺图时不得宣称完整套图成功。

## 6. 验收

| 指标 | 定义 |
|---|---|
| 首套图时间 | 参考图和图种就绪后，到计划镜头都有成功结果。分开记录编排耗时与 provider 耗时 |
| 商品保真 | 人工核对外形、颜色/材质、logo/关键文字、文字策略。失败图仍保留 |
| 修改闭环 | 能重跑单镜头或局部修，不必重建商品和整张图 |
| 配方复用 | 第二件商品预览并应用同一结构时，不携带上一件商品的身份和像素 |
| 可恢复性 | 刷新、SSE 重连或单节点失败后，能从数据库事实继续 |

首轮质量样本建立前不写虚假百分比。自动打分不是本增量的完成条件。

## 7. 页面级状态

每个主页面必须显式处理：首次加载、空数据、部分加载、保存中、冲突、可恢复失败、不可恢复失败、登录失效。Toast 不能成为唯一结果记录。

工作台信息架构：生产主区永远最大；详情是当前对象；Agent 是协作者。生产主区不能因为 Agent 打开而变成不可操作的背景。
